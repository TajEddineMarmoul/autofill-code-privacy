Overview

In plain language: the extension processes verification data on your device. The developer does not receive your Gmail messages, browsing activity, OAuth token, or verification codes.

This policy explains the information AutoFill Code handles to provide its single purpose: finding recent email verification codes and offering or filling them in compatible website fields.

Data handled by the extension

Chrome uses broad disclosure categories even when processing happens only on the user's device. AutoFill Code handles the following categories:

Personally identifiable informationEmail addresses found in Gmail headers or displayed beside a verification form.
Authentication informationA short-lived Google OAuth token and extracted one-time verification codes.
Personal communicationsA bounded set of recent Gmail message headers, snippets, and text needed to identify codes.
Web browsing activityThe current website origin for open tabs where OTP matching is active. The extension does not build a persistent browsing-history list.
User activityOnly a recognized Send code or Resend code action and its timestamp, used to distinguish a new verification attempt from an old one.
Website contentNearby OTP labels and input metadata, such as expected length, accepted characters, and a displayed recipient address.

The extension also handles the selected fill behavior, Gmail scan cursor and timestamps, applied-code identifiers, and temporary per-tab detection state.

AutoFill Code does not intentionally collect health information, financial or payment information, precise location, passwords, general click activity, keystroke logs, or page contents unrelated to finding and filling an OTP field.

How the data is used

  1. Authenticate the user's read-only Gmail connection.
  2. Inspect a limited recent-email window for active verification codes.
  3. Match a code to the current website, compatible OTP field, recipient, and verification attempt.
  4. Fill or present that code according to the user's chosen behavior.
  5. Prevent expired or previously applied codes from being reused automatically.

Data is not used for advertising, profiling, analytics, credit decisions, lending, or any purpose unrelated to verification-code filling.

Storage and retention

Data is stored in extension-local or session storage on the user's device.

  • OAuth access tokens are short-lived and removed when Gmail is disconnected.
  • Cached verification codes are removed after their stated expiry or a bounded default lifetime.
  • Applied-code records are retained only until the corresponding code expires.
  • The Gmail scan cursor remains locally so later checks can continue from the last completed scan instead of rereading the inbox.
  • Current website origins, OTP-field metadata, and verification-attempt timestamps use temporary session storage and end with the browser session or tab cleanup.

Disconnecting Gmail clears the token, active-code cache, and Gmail scan state. Removing the extension or clearing its stored data removes the remaining local preferences.

Sharing and transmission

AutoFill Code communicates directly with Google OAuth and the Gmail API over HTTPS. It does not send Gmail data, website content, OAuth tokens, verification codes, or browsing activity to the developer, analytics providers, advertisers, or data brokers.

When filling is enabled, the matched code is written into the detected website field. The extension does not submit the form on the user's behalf.

Remote code

AutoFill Code does not download or execute remote JavaScript, WebAssembly, or other executable logic. All executable code and interface assets are included in the published extension package. Google OAuth and Gmail API responses are treated only as data.

Security

Google communication uses HTTPS. OAuth tokens and cached data remain within Chrome extension storage and are not exposed to website scripts. The extension requests read-only Gmail access and limits both its first and subsequent inbox scans by time and message count.

Your choices

Users can switch between automatic filling, confirmation before filling, and disabled filling. Gmail can be disconnected from the extension menu at any time. Users can also remove the extension or clear its stored data through Chrome.

Google API and Chrome Web Store Limited Use

AutoFill Code's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

AutoFill Code's handling of user data also complies with the Chrome Web Store User Data Policy, including its Limited Use requirements. The extension does not allow humans to read user data.

Changes to this policy

Material changes to data handling will be reflected on this page and in the Chrome Web Store privacy disclosures before the related extension update is published. The effective date at the top of this page will also be updated.

Contact

For privacy questions, open an issue in the public privacy repository. Do not include email contents, access tokens, verification codes, or other personal data in a public issue.
